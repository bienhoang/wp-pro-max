# Port wp-classic skill from claude-code-wp-toolkit

## Overview

Import the conventions from `alessioarzenton/claude-code-wp-toolkit`'s `wp-classic` stack skill into WP Pro Max as a first-class, manifest-aware capability. The deliverables are:

1. `skills/wp-classic/SKILL.md` — a user-invocable skill that documents classic PHP theme conventions for WordPress 7.x.
2. `references/classic-acf.md` — the canonical reference consumed by `theme-conversion` and `wp-scaffold` when `strategy == "classic-acf"`.
3. `skills/wp-classic/references/code-review-checklist.md` and `component-workflow.md` — ported generic helper references.
4. Minor updates to `theme-conversion/SKILL.md`, `wp-scaffold/SKILL.md`, and `agents/wp-theme-developer.md` to wire in the new reference and resolve template-location assumptions.

The port is **adaptive, not a transplant**: Bedrock/DDEV assumptions are replaced with WP Pro Max's standard `wp-env` flow; `{{VAR}}` placeholders are replaced with `wp-build.json` manifest fields; Figma/design-dir-specific workflow steps are stripped because WP Pro Max v1 has no Figma bridge.

## Source Anatomy

The source skill is a **stack skill** that stays always-active in a per-project `.claude/` configuration. Its key layers are:

- **Stack declaration**: WordPress 6.x + Bedrock, PHP 8.2+, Classic PHP theme, optional Tailwind CSS 4 prefix, Standard ACF Pro.
- **Project structure**: `templates/`, `parts/`, `inc/`, `assets/`, `acf-json/`, root templates (`front-page.php`, `page.php`, etc.).
- **Naming**: kebab-case template files, `snake_case` functions with theme prefix, `PascalCase` classes, `UPPER_SNAKE_CASE` constants.
- **Code style**: WPCS (tabs), Prettier for JS/CSS.
- **Template pattern**: `get_template_part('parts/name', 'variant', $args)` with `$args` defaults inside partials.
- **Registration code**: `register_post_type()` / `register_taxonomy()` in `inc/post-types.php`.
- **ACF pattern**: `acf_register_block_type()` in `inc/acf-blocks.php`; field groups authored in GUI and exported to `acf-json/`.
- **Enqueue pattern**: `inc/enqueue.php` with `wp_enqueue_style/script`, `get_theme_file_uri()`.
- **Anti-patterns**: Blade, Acorn, `@include`, hardcoded colors, unsafe echo, inline scripts.

## Decision Matrix

| Decision | Source's Way | Our Way | Recommendation |
|---|---|---|---|
| Packaging | Per-project `.claude/skills/stacks/wp-classic/` installed by `init.sh` | Kit plugin `skills/wp-classic/` + `references/classic-acf.md` | Port as kit-level skill + reference |
| WordPress target | 6.x | **7.x** (per user revision) | Update skill/reference to target WordPress 7.x |
| Activation | Always-active stack skill | User-invocable; referenced by `theme-conversion`/`wp-scaffold` | Make user-invocable |
| Template location | `templates/` folder | Theme root templates (with `templates/` as optional) | Prefer root templates for auto-generation |
| Placeholders | `{{VAR}}` substituted by installer | Read from `wp-build.json` at generation time | No `{{VAR}}` in ported text |
| Code-review / component-workflow | Per-project generated skills | Generic reference docs under `skills/wp-classic/references/` | Port as references, not generated skills |
| Figma/design-dir workflow | Integrated with `figma-bridge` | Not available in WP Pro Max v1 | Strip Figma steps; keep generic rules |
| Bedrock support | First-class assumption | Optional note only | Target standard wp-env; mention Bedrock as optional |
| License | GPL-3.0 | MIT | Rewrite idiomatically; attribute source |
