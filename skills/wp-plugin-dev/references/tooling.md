# Tooling Reference

Dev-loop bodies: Composer, PHPCS, PHPUnit, readme.txt, and the packaging contract.
All templates are embedded here; `plugin-env-bootstrap.sh` and
`plugin-package.sh` extract them as needed.

## `composer.json`

<!-- file: composer.json -->
```json
{
  "name": "netko-solution/__SLUG__",
  "description": "__NAME__",
  "type": "wordpress-plugin",
  "license": "GPL-2.0-or-later",
  "require": {
    "php": ">=7.4"
  },
  "require-dev": {
    "squizlabs/php_codesniffer": "^3.9",
    "wp-coding-standards/wpcs": "^3.0",
    "phpunit/phpunit": "^9.6",
    "yoast/phpunit-polyfills": "^1.1"
  },
  "autoload": {
    "psr-4": {
      "__NAMESPACE__\\\\": "src/"
    }
  },
  "scripts": {
    "lint": "phpcs",
    "test": "phpunit"
  },
  "config": {
    "allow-plugins": {
      "dealerdirect/phpcodesniffer-composer-installer": true
    }
  }
}
```

## `tests/bootstrap.php`

<!-- file: tests/bootstrap.php -->
```php
<?php
/**
 * PHPUnit bootstrap.
 *
 * @package __NAMESPACE__
 */

// Load the WordPress test environment provided by wp-env.
require '/wordpress-phpunit/includes/bootstrap.php';

// Load this plugin and re-fire init so feature hooks registered by the plugin run.
require_once dirname( __DIR__ ) . '/__SLUG__.php';
do_action( 'init' );
```

## `tests/test-activation.php`

<!-- file: tests/test-activation.php -->
```php
<?php
/**
 * Smoke test: plugin activation and autoload.
 *
 * @package __NAMESPACE__
 */

namespace __NAMESPACE__\Tests;

/**
 * Activation smoke test.
 */
class Test_Activation extends \WP_UnitTestCase {

	/**
	 * Plugin bootstrap class loads.
	 */
	public function test_plugin_class_exists() {
		$this->assertTrue( class_exists( '__NAMESPACE__\\Plugin' ) );
	}

	/**
	 * A sub-namespaced feature class autoloads without Composer.
	 */
	public function test_feature_class_autoloads() {
		$this->assertTrue( class_exists( '__NAMESPACE__\\PostTypes\\ItemPostType' ) );
	}

	/**
	 * CPT registered by the plugin is present.
	 */
	public function test_cpt_registered() {
		$post_types = get_post_types();
		$this->assertArrayHasKey( 'item', $post_types );
	}
}
```

## `readme.txt`

The scaffold already writes a `readme.txt` placeholder from
`plugin-architecture.md`. The tooling reference simply documents the expected
shape: stable header with `__NAME__`, `__VERSION__`, `__SLUG__` tags, a
Description section, and a Changelog.

## `.wp-env.json`

Generated by `plugin-env-bootstrap.sh`, not copied from a template. It maps the
plugin directory into the container:

```json
{
  "core": "WordPress/WordPress#__WP_VERSION__",
  "phpVersion": "__PHP_VERSION__",
  "plugins": [],
  "mappings": {
    "wp-content/plugins/__SLUG__": "."
  }
}
```

## Packaging allowlist

`plugin-package.sh` builds `dist/<slug>-<version>.zip` from an explicit
allowlist:

- `<slug>.php`
- `uninstall.php`
- `readme.txt`
- `inc/`
- `src/`
- `languages/`
- `blocks/*/build/`
- `vendor/` (only after `composer install --no-dev`)

The script force-includes `blocks/*/build/` even though it is git-ignored, and
fails the build if any non-allowlisted file or known secret pattern
(`.env`, `*.key`, `*.pem`, `wp-config.php`, `wp-plugin.json`, `.wp-env.json`,
`composer.json`, `package.json`, dev configs) is present, or if a declared block
lacks `build/block.json`.
